
`~/slash/slash-api`, `~/slash/slash-agent`).

## 방법 1 — 자동 스크립트 (추천)

아래 스크립트를 `run-echo-test.sh`로 저장하고 실행하면 mock-api → 로컬 에이전트 → 웹을
순서대로 백그라운드로 띄우고, 준비되면 브라우저로 `/dev/echo-test`를 자동으로 연다.
(팀 단톡방에 스크립트 파일을 직접 공유할 예정이라 여기서는 코드블록으로만 남긴다.)

저장 위치: `slash-web-test`/`slash-api-test`/`slash-agent-test` 세 저장소와 같은
부모 폴더 아래(예: `~/slash/run-echo-test.sh`).

```bash
chmod +x run-echo-test.sh

./run-echo-test.sh            # 기본값: contract-agent CLI로 에이전트까지 전부 자동 실행
./run-echo-test.sh electron   # dmg 없이 소스에서 Electron 앱을 빌드해 자동 실행
./run-echo-test.sh manual     # 에이전트는 자동 실행하지 않음 — 다운로드한 dmg를 직접 실행했을 때
```

`electron` 모드는 dmg를 받지 않고도 저장소를 pull받은 상태 그대로 소스에서 바로
에이전트를 자동 실행한다는 점에서 `cli` 모드와 같은 목적이지만, 실제 Electron 앱(메뉴바
아이콘)이 뜬다는 차이가 있다. `contract-agent` CLI와 로깅 경로가 동일해서 이론상 똑같이
동작해야 하지만, GUI 세션이 제한된 환경(예: 일부 CI·자동화 셸)에서는 Electron이 정상적으로
안 뜰 수 있다 — 그런 경우 `manual` 모드로 바꿔서 직접 실행한다.

종료는 `Ctrl+C` — 자동 실행한 프로세스가 전부 정리된다. `manual` 모드로 직접 실행한
에이전트는 별도로 종료해야 한다.

<summary>run-echo-test.sh 전체 내용 (펼치기)</summary>

```bash
#!/usr/bin/env bash
# "hello slash" COMMAND 명령 테스트 종단 실행 스크립트
#
# mock-api -> 로컬 에이전트 -> 웹(vite dev server) 순으로 백그라운드에서 띄우고,
# 준비되면 브라우저로 /dev/echo-test를 자동으로 연다.
#
# 전제: slash-web, slash-api, slash-agent 세 저장소가 이 스크립트와 같은 부모
# 디렉터리 아래 형제 폴더로 존재해야 한다(예: ~/slash/slash-web, ~/slash/slash-api,
# ~/slash/slash-agent). 각 저장소는 -test 브랜치로 미리 체크아웃돼 있어야 한다.
#
# 사용법:
#   ./run-echo-test.sh            에이전트까지 전부 자동 실행 (contract-agent CLI, 기본값)
#   ./run-echo-test.sh electron   에이전트를 dmg 없이 소스에서 빌드해 Electron 앱으로 자동 실행
#   ./run-echo-test.sh manual     에이전트는 자동 실행하지 않음 — 다운로드한 dmg를 직접
#                                 실행했을 때 쓴다
#
# 참고: electron 모드는 contract-agent CLI와 동일한 로깅 경로(agent-app이 내부적으로
# contract-agent 로직을 그대로 재사용)를 쓰기 때문에 이론상 동일하게 동작해야 하지만,
# GUI 세션이 제한된 환경(headless 서버, 일부 CI/자동화 셸)에서는 Electron이 정상적으로
# 뜨지 않을 수 있다. 그런 경우 manual 모드로 전환해서 직접 실행할 것.
#
# 종료: Ctrl+C (백그라운드 프로세스 전부 정리됨)

set -euo pipefail

MODE="${1:-cli}"
case "$MODE" in
  cli|electron|manual) ;;
  --no-agent) MODE="manual" ;;  # 이전 옵션명 호환
  *) echo "사용법: $0 [cli|electron|manual]" >&2; exit 1 ;;
esac

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"

# BASE_DIR 환경변수로 직접 지정했으면 그걸 쓰고, 아니면 slash-web/slash-api/slash-agent이
# 형제로 있는 폴더를 스크립트 위치부터 최대 3단계 위까지 올라가며 찾는다. 스크립트를
# 어디에 두든(예: ~/slash/, ~/slash/not_push_git_docs/, ~/slash/slash-docs/test-sandbox/)
# 동작하도록 하기 위함.
if [ -n "${BASE_DIR:-}" ]; then
  BASE_DIR="$(cd "$BASE_DIR" && pwd)"
else
  CANDIDATE="$SCRIPT_DIR"
  for _ in 1 2 3; do
    if [ -d "$CANDIDATE/slash-web" ] && [ -d "$CANDIDATE/slash-api" ] && [ -d "$CANDIDATE/slash-agent" ]; then
      BASE_DIR="$CANDIDATE"
      break
    fi
    CANDIDATE="$(cd "$CANDIDATE/.." && pwd)"
  done
  [ -n "${BASE_DIR:-}" ] || { echo "slash-web/slash-api/slash-agent이 같이 있는 상위 폴더를 찾을 수 없습니다. BASE_DIR 환경변수로 직접 지정하세요 (예: BASE_DIR=~/slash ./run-echo-test.sh)." >&2; exit 1; }
fi

WEB_DIR="$BASE_DIR/slash-web"
API_DIR="$BASE_DIR/slash-api"
AGENT_CLI_DIR="$BASE_DIR/slash-agent/contract-agent"
AGENT_APP_DIR="$BASE_DIR/slash-agent/agent-app"

LOG_DIR="$(mktemp -d /tmp/echo-test-logs.XXXXXX)"
PIDS=()

log() { printf '\n\033[1;36m[echo-test]\033[0m %s\n' "$1"; }
fail() { printf '\n\033[1;31m[echo-test 실패]\033[0m %s\n' "$1" >&2; exit 1; }

cleanup() {
  log "종료 중 — 백그라운드 프로세스 정리"
  for pid in "${PIDS[@]:-}"; do
    kill "$pid" >/dev/null 2>&1 || true
  done
}
trap cleanup EXIT INT TERM

# 0. 사전 점검
[ -d "$WEB_DIR" ] || fail "slash-web 저장소를 찾을 수 없습니다: $WEB_DIR"
[ -d "$API_DIR" ] || fail "slash-api 저장소를 찾을 수 없습니다: $API_DIR"
if [ "$MODE" = "cli" ]; then
  [ -d "$AGENT_CLI_DIR" ] || fail "slash-agent/contract-agent를 찾을 수 없습니다: $AGENT_CLI_DIR"
elif [ "$MODE" = "electron" ]; then
  [ -d "$AGENT_APP_DIR" ] || fail "slash-agent/agent-app을 찾을 수 없습니다: $AGENT_APP_DIR"
fi

for dir in "$WEB_DIR" "$API_DIR"; do
  branch="$(git -C "$dir" branch --show-current)"
  case "$branch" in
    *-test) ;;
    *) log "경고: $dir 이 -test 브랜치가 아닙니다 (현재: $branch)" ;;
  esac
done

# 1. 의존성 설치 (node_modules 없을 때만)
log "의존성 확인 중..."
[ -d "$API_DIR/node_modules" ] || (cd "$API_DIR" && npm install)
[ -d "$WEB_DIR/node_modules" ] || (cd "$WEB_DIR" && npm install)
if [ "$MODE" = "cli" ]; then
  [ -d "$AGENT_CLI_DIR/node_modules" ] || (cd "$AGENT_CLI_DIR" && npm install)
elif [ "$MODE" = "electron" ]; then
  [ -d "$AGENT_APP_DIR/node_modules" ] || (cd "$AGENT_APP_DIR" && npm install)
fi

# 2. mock-api 실행
log "mock-api 실행 중 (포트 4000)..."
(cd "$API_DIR" && npm run start) > "$LOG_DIR/mock-api.log" 2>&1 &
PIDS+=($!)

for i in $(seq 1 20); do
  grep -q "listening on :4000" "$LOG_DIR/mock-api.log" 2>/dev/null && break
  sleep 0.5
  [ "$i" -eq 20 ] && fail "mock-api가 10초 안에 기동하지 않았습니다. 로그: $LOG_DIR/mock-api.log"
done
log "mock-api 준비 완료"

# 3. 로컬 에이전트 실행
ACCOUNT_HINT="contract-agent-tester@example.com"
case "$MODE" in
  cli)
    log "로컬 에이전트 실행 중 (contract-agent CLI)..."
    (cd "$AGENT_CLI_DIR" && npm run start) > "$LOG_DIR/agent.log" 2>&1 &
    PIDS+=($!)
    for i in $(seq 1 20); do
      grep -q "READY" "$LOG_DIR/agent.log" 2>/dev/null && break
      sleep 0.5
      [ "$i" -eq 20 ] && fail "에이전트가 10초 안에 READY 상태가 되지 않았습니다. 로그: $LOG_DIR/agent.log (electron 또는 manual 모드도 시도해볼 것)"
    done
    log "에이전트 준비 완료 ($ACCOUNT_HINT)"
    ;;
  electron)
    ACCOUNT_HINT="agent-app-tester@example.com"
    log "로컬 에이전트 실행 중 (dmg 없이 소스에서 Electron 앱 빌드+실행)..."
    (cd "$AGENT_APP_DIR" && npm run start) > "$LOG_DIR/agent.log" 2>&1 &
    PIDS+=($!)
    for i in $(seq 1 40); do
      grep -q "READY" "$LOG_DIR/agent.log" 2>/dev/null && break
      sleep 0.5
      [ "$i" -eq 40 ] && fail "에이전트가 20초 안에 READY 상태가 되지 않았습니다. 로그: $LOG_DIR/agent.log — GUI 세션이 제한된 환경일 수 있으니 manual 모드로 다시 시도해볼 것"
    done
    log "에이전트 준비 완료 (메뉴바 아이콘 확인, $ACCOUNT_HINT)"
    ;;
  manual)
    ACCOUNT_HINT="agent-app-tester@example.com (직접 실행한 에이전트 계정과 일치해야 함)"
    cat <<'INNEREOF'

--------------------------------------------------------------
manual 모드 — 에이전트는 자동 실행하지 않습니다.
다운로드한 dmg를 Applications에 설치한 뒤 실행하세요
(최초 1회는 우클릭 -> 열기 필요).

에이전트가 READY 상태가 될 때까지 몇 초 기다린 뒤 계속합니다.
--------------------------------------------------------------
INNEREOF
    sleep 5
    ;;
esac

# 4. 웹 dev 서버 실행
log "웹 dev 서버 실행 중 (포트 5173)..."
(cd "$WEB_DIR" && npm run dev) > "$LOG_DIR/web.log" 2>&1 &
PIDS+=($!)

for i in $(seq 1 20); do
  grep -q "Local:" "$LOG_DIR/web.log" 2>/dev/null && break
  sleep 0.5
  [ "$i" -eq 20 ] && fail "웹 서버가 10초 안에 기동하지 않았습니다. 로그: $LOG_DIR/web.log"
done
log "웹 서버 준비 완료"

# 5. 브라우저 자동으로 열기
URL="http://localhost:5173/dev/echo-test"
log "브라우저에서 $URL 여는 중..."
open "$URL" 2>/dev/null || true

cat <<EOF

--------------------------------------------------------------
모든 서비스가 준비됐습니다. 로그는 $LOG_DIR 에 있습니다.

$URL 에서 "시험 로그인 이메일"을 $ACCOUNT_HINT
로 바꾸고 "보내기"를 눌러 테스트하세요.

이 창을 Ctrl+C로 종료하면 mock-api / 웹 서버(및 자동 실행한 에이전트)가 전부 정리됩니다.
manual 모드로 실행했다면 직접 실행한 에이전트는 별도로 종료해야 합니다.
--------------------------------------------------------------
EOF

wait
```

## 방법 2 — 수동으로 하나씩 실행

### 1. mock-api (slash-api-test)
```bash
cd slash-api
npm install       # 처음 한 번만
npm run start      # 포트 4000
```
`[mock-api] listening on :4000` 로그가 뜨면 준비 완료.

### 2. 로컬 에이전트 실행 방법 — 셋 중 하나

**A) 가벼운 CLI (빌드 불필요)**
```bash
cd slash-agent/contract-agent
npm install
npm run start
```
→ 자동 로그인 계정: `contract-agent-tester@example.com`

**B) 소스에서 Electron 앱 직접 실행**
```bash
cd slash-agent/agent-app
npm install
npm run start
```
→ 자동 로그인 계정: `agent-app-tester@example.com`

**C) 빌드 없이 dmg 다운로드해서 바로 실행**
1. https://github.com/LikeLionTeam4/slash-agent/releases/tag/slash-agent-test-command-v1
   에서 `Slash Agent-0.1.1-arm64.dmg` 다운로드
2. 더블클릭해 마운트 → `Slash Agent.app`을 `Applications` 폴더로 드래그
3. 아래 "Gatekeeper 안내"대로 최초 1회 실행
→ 자동 로그인 계정: `agent-app-tester@example.com` (B와 동일)

> ⚠️ `v0.1.0`/`v0.1.1` 정식 릴리즈 dmg는 쓰면 안 된다 — `dev` 브랜치 기준이라 COMMAND를
> 모른다. 반드시 위 `slash-agent-test-command-v1` 태그의 dmg를 쓴다.

#### Gatekeeper 안내 (B, C 공통 — 미서명 앱 최초 실행)

1. **기본**: `Slash Agent.app`을 우클릭(또는 Control+클릭) → **열기** → 대화상자에서
   **열기** 클릭
2. **"휴지통으로 이동"만 뜨고 "열기"가 없는 경우**: `시스템 설정 → 개인정보 보호 및 보안`
   → 아래로 스크롤 → `"Slash Agent"이(가) 차단되었습니다` 옆 **"확인 없이 열기"** 클릭
   → 인증 → 다시 실행하면 "열기" 버튼이 있는 대화상자가 뜬다
3. **그래도 안 되면 터미널에서**:
   ```bash
   xattr -cr "/Applications/Slash Agent.app"
   # 그래도 안 되면
   codesign --deep --force --sign - "/Applications/Slash Agent.app"
   ```

### 3. 웹 실행 (slash-web-test)
```bash
cd slash-web
npm install
npm run dev     # http://localhost:5173
```

### 4. 테스트

브라우저로 `http://localhost:5173/dev/echo-test` 접속 (로그인 불필요).

- mock-api 주소: `http://localhost:4000` (기본값 그대로)
- 시험 로그인 이메일: 페이지 기본값이 `contract-agent-tester@example.com`이라 **2번에서
  A(CLI)를 썼으면 그대로 두면 된다.** B/C(Electron/dmg)를 썼다면 `agent-app-tester@example.com`으로
  바꿔 입력해야 한다.
- 메시지: `hello slash` (기본값)
- **보내기** 클릭 → 결과와 이벤트 타임라인이 화면에 표시되면 성공

## 자주 하는 실수

- `localhost:4000`으로 직접 들어가면 `Cannot GET /`가 뜬다 — 웹은 반드시 **5173** 포트로
  접속한다.
- "기기 0개 중 READY 상태가 없습니다"가 뜨면 → 이메일이 실행한 에이전트 계정과 안 맞는
  경우다. 위 2번의 계정 표를 다시 확인한다.

## 종료

각 터미널에서 `Ctrl+C`. mock-api는 인메모리 저장소라 재시작하면 페어링 정보가
날아가므로, 다시 테스트하려면 에이전트도 같이 재시작해서 재페어링해야 한다.
